WX Wallet API

REST 규격 v0.2.0 로컬 시연

WX_API의 로컬 REST와 내부 INet은 같은 시연 원장을 사용합니다. 송금 성공과 결과가 확인된 예금주 조회가 과금 대상입니다.

Wallet 가상 송금 접수

POST /api/v1/wallet/transfer

요청 헤더

헤더필수설명
X-WX-Key예고객사 범위를 판별하는 REST 전용 키. 요청 본문으로 고객사를 지정할 수 없습니다.
Content-Type예application/json. UTF-8 기준 본문 최대 8,192바이트.
X-Trace-Id아니요영숫자 8자리. 없거나 형식이 다르면 서버가 발급합니다. 응답 헤더와 본문의 값은 같습니다.

요청 필드

필드타입필수설명
requestIdstring예고객사 요청번호. 앞뒤 공백을 제외하고 1~80자. 같은 요청을 재시도할 때 재사용.
walletIdstring예고객사 소유의 Wallet ID.
amountstring예원 단위 정수 문자열. 1~999,999,999,999원. 선행 0·쉼표·소수점 입력 불가.
recipientstring예시연 수취인 표시명. 앞뒤 공백을 제외하고 1~80자.
outcomestring예가상 송금 결과. success, failed, unknown 중 하나.

요청 예시

curl --request POST 'http://127.0.0.1:18099/api/v1/wallet/transfer' \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/json' \
  --header 'X-WX-Key: <발급된 REST 키>' \
  --header 'X-Trace-Id: WXAPI001' \
  --data '{"requestId":"WX-20261119-0001","walletId":"W001","amount":"1000","recipient":"가상 수취인","outcome":"success"}'

정상 응답

HTTP 200과 result: true는 가상 거래가 원장에 접수됐다는 뜻입니다. outcome의 시연 결과와 구분합니다. 성공은 원금과 후불 수수료를 반영하고, 확정 실패는 원금을 환입하며, 결과 불명은 원금을 예약한 상태로 남깁니다.

{
  "result": true,
  "traceId": "WXAPI001",
  "data": {
    "id": "T65000000000A1B2C3",
    "replayed": false
  }
}

같은 고객사에서 동일한 requestId와 요청 내용으로 재호출하면 같은 거래번호와 replayed: true를 반환합니다. 원장 반영은 한 번만 이루어집니다. 같은 요청번호로 내용을 바꾸면 TX409입니다. 응답을 받지 못한 경우 새 번호를 발급하지 말고 원래 번호와 요청 내용을 유지하세요.

예금주 조회 시연

POST /api/v1/wallet/holder는 같은 인증 헤더와 requestId, walletId, outcome을 받습니다. matched와 mismatch는 결과가 확인된 통신이며 unknown은 결과 미확인입니다. 본사가 설정한 단가를 적용하고 일별로 차감합니다.

거래번호 체계

항목발급역할
requestId고객사멱등성에 사용하는 요청번호.
data.idWX 서버접수된 송금 거래의 고유 번호. HUB_ADM의 거래번호(trxId) 체번 방식을 적용합니다.
traceId호출자 또는 서버8자리 요청 추적번호.

REST 거래번호는 HUB_ADM과 같은 TX24_LIB IDUtils.getUnique("T")로 발급합니다. 구현 기준 총 18자로, T + epoch 밀리초 문자열의 인덱스 2부터 13 직전까지 11자리 + UUID 앞 6자리의 대문자 16진수입니다. 예시는 T65000000000A1B2C3입니다. 동일 요청 재응답에는 먼저 저장한 번호를 사용합니다. 기관 전문번호는 별도 식별자입니다.

오류 코드

HTTP코드설명

401TX401REST 연동 키가 없거나 올바르지 않습니다.

409TX409요청번호 충돌, API 중지시간, Wallet 또는 본사 모계좌 송금 가능 잔액 부족.
413TX400요청 본문은 UTF-8 기준 8,192바이트 이하여야 합니다.

{
  "result": false,
  "code": "TX409",
  "message": "API 중지시간입니다. 신규 송금을 접수할 수 없습니다.",
  "traceId": "WXAPI001"
}

현재 동작하는 INet 호출

로컬 수신 기본값은 127.0.0.1:18098, 대상은 /api/internal/demo/payout입니다. INet data에 method=INet, x-wx-key, JSON 문자열인 payload, 선택 사항인 x-trace-id를 넣습니다. 키에 연결된 고객사는 서버 설정으로 고정합니다. 응답의 업무 JSON은 INet data의 response에서 읽습니다.

신규 가상 송금은 REST와 INet 모두 HUB 체번을 사용합니다. 이전 P로 시작하는 거래는 기존 요청번호로 재조회할 수 있습니다.

WX 데이터베이스 연동

서버의 키 환경에 맞는 고객사 키와 등록된 접속 IP를 확인합니다. 잔액 조회에는 POST /api/v1/wallet/balance와 walletId, 송금 장부 결과에는 POST /api/v1/wallet/inquiry와 trxId를 사용합니다. HYPHEN 시험자료 준비 전 송금과 예금주 조회는 인증 후 HTTP 503을 반환합니다. WX 데이터베이스 REST 규격

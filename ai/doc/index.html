WX Wallet API

REST 규격 v0.6.0 · TX24_DOC Wallet 기준

모든 요청에 Authorization: wk_…와 Content-Type: application/json을 사용합니다. 인증 키로 고객사를 확인하고, 등록된 접속 IP를 검사한 뒤 키와 연결된 Wallet으로 처리합니다.

응답의 walletId에 키와 연결된 Wallet ID가 들어갑니다. 인증 및 Wallet 설정 오류에서는 Wallet ID를 반환하지 않습니다.

기능POST 경로필수 JSON 필드
잔액 조회/api/v1/wallet/balance빈 객체 {}
예금주 조회/api/v1/wallet/holdertrackId, bankCd, accntNo
송금/api/v1/wallet/transfertrackId, bankCd, accntNo, amount, checksum
송금 결과 조회/api/v1/wallet/inquirytrackId, trxDay

잔액 조회

{}를 보내면 연결된 Wallet의 장부잔액(balance)과 현재 이체가능잔액(availableBalance)을 받습니다. 현재 이체가능잔액은 장부잔액에서 송금 예약액과 관리자 보류액을 뺀 값입니다.

{
  "resultCd": "0000", "resultMsg": "정상", "advanceMsg": "정상조회",
  "createAt": "20261120103000", "traceId": "WXTEST01",
  "walletId": "SAMPLE-WALLET", "balance": 100000, "availableBalance": 95000
}

예금주 조회

{"trackId":"H001","bankCd":"004","accntNo":"0000000000"}

기관 조회가 성공하면 기관이 확인한 예금주명을 holder에 제공합니다.

현재 응답

{"resultCd":"W003","resultMsg":"접수 중지","advanceMsg":"HYPHEN 기관 연결 준비 중으로 접수가 중지되었습니다.","createAt":"20261120103000","traceId":"WXTEST01","walletId":"SAMPLE-WALLET"}

송금 요청

{
  "trackId": "T001", "bankCd": "004", "accntNo": "0000000000", "amount": 1000,
  "sender": "상점명", "checksum": "77f4f0989e9b7f9d9c1e6bbc132af0a1870117085522756cd54f3e53bc95b7be"
}

trackId는 최대 64자이며 은행코드 3자리와 숫자로 된 계좌번호는 문자열로 보냅니다. amount는 최대 18자리의 양의 원화 정수입니다. sender, holder, note는 선택 항목입니다. 표에 정의된 필수값과 세 선택값만 송금 본문에 사용합니다.

checksum 계산

키에 연결된 walletId를 서명에 사용합니다. 연동 설정 또는 잔액 조회 응답에서 확인할 수 있습니다. 서명 키는 wk_ 접두사를 포함한 Authorization 원문이며, 결과는 64자리 소문자 16진수입니다.

아래 순서의 값을 LF(\n)로 연결하고 UTF-8로 인코딩합니다. 금액은 10진수 정수 문자열로 변환하고, 계좌번호의 앞자리 0과 선택값의 공백은 유지합니다. 생략한 선택값은 빈 문자열로 넣고, 마지막 값 뒤에 구분자를 추가하지 않습니다. 문자열 안의 제어 문자와 JSON 중복 키는 허용하지 않습니다.

import hashlib
import hmac

def transfer_checksum(api_key, wallet_id, request):
    fields = [
        "WX-WALLET-TRANSFER-V1", wallet_id,
        request["trackId"], request["bankCd"], request["accntNo"], str(request["amount"]),
        request.get("sender", ""), request.get("holder", ""), request.get("note", ""),
    ]
    return hmac.new(api_key.encode("utf-8"), "\n".join(fields).encode("utf-8"), hashlib.sha256).hexdigest()

위 요청의 테스트 벡터는 SAMPLE-WALLET과 문서 예제용 키 wk_example_for_documentation_only로 계산했습니다. 서명이 없거나 형식이 틀리거나 요청값과 일치하지 않으면 W001을 반환합니다.

현재 응답

{"resultCd":"W003","resultMsg":"접수 중지","advanceMsg":"HYPHEN 기관 연결 준비 중으로 접수가 중지되었습니다.","createAt":"20261120103000","traceId":"WXTEST01","walletId":"SAMPLE-WALLET"}

송금 거래를 반환할 때의 응답 형식

{
  "resultCd":"0000", "resultMsg":"정상", "advanceMsg":"정상이체", "traceId":"WXTEST01",
  "walletId":"SAMPLE-WALLET", "trxId":"WX2601123456", "trackId":"T001", "acqTrxId":"261120000123",
  "status":"success", "bankCd":"004", "accntNo":"00000***00", "sender":"상점명", "holder":"홍길동", "amount":1000,
  "requestedAt":"20261120103002", "createAt":"20261120103004", "balance":99000, "availableBalance":null
}

accntNo에는 마스킹한 수취 계좌번호만 제공합니다. 거래 시각은 서울 기준 yyyyMMddHHmmss 문자열입니다.

  • requestedAt은 원거래의 TRX_TRANSFER.reqDate입니다.
  • createAt은 성공 거래에서 유효한 TRX_WALLET.acqTrxDate를 우선 사용합니다. 연결은 TRX_TRANSFER.walletTrxId로 찾으며, 기관 시각을 확인할 수 없으면 TRX_TRANSFER.regDate를 사용합니다. 두 기준으로 시각을 확정할 수 없으면 null입니다.

송금 결과 조회

{"trackId":"T001","trxDay":"20261120"}

trxDay는 서울 기준 송금 완료일 또는 접수일(YYYYMMDD)입니다. 조회 응답의 resultCd가 0000이면 rootResultCd로 원거래를 확인합니다. 원거래 코드 0000은 성공, 빈 값은 진행 중, W00X는 결과 확인 중입니다. 응답이 끊기면 기존 주문번호와 요청일로 거래부터 조회합니다. 송금 응답과 같은 원거래 필드를 제공하며, resultCd와 resultMsg는 조회 결과, rootResultCd와 rootResultMsg는 원거래 결과입니다.

기존 송금이 성공한 경우

{
  "resultCd":"0000", "resultMsg":"정상", "advanceMsg":"정상조회", "traceId":"WXTEST02",
  "rootResultCd":"0000", "rootResultMsg":"정상이체",
  "walletId":"SAMPLE-WALLET", "trxId":"WX2601123456", "trackId":"T001", "acqTrxId":"261120000123",
  "status":"success", "bankCd":"004", "accntNo":"00000***00", "sender":"상점명", "holder":"홍길동", "amount":1000,
  "requestedAt":"20261120103002", "createAt":"20261120103004", "balance":99000, "availableBalance":null
}

원거래에 기록된 잔액만 제공하며, 과거에 저장하지 않은 값은 null입니다. 현재 조회에서 원장에 연결된 거래의 balance는 TRX_WALLET.balanceAfter이고, 기존 거래에는 이체가능잔액 기록이 없습니다.

웹훅 통지

송금 결과가 확정되거나 입금이 Wallet 잔액에 반영되면 등록한 수신처로 통지합니다. 수신처는 본사에 등록을 요청하며 Wallet마다 여러 개를 둘 수 있습니다.

이벤트보내는 때
transfer.settled송금 결과가 성공 또는 실패로 확정된 때. 통신장애 재조회로 확정된 건도 같습니다.
deposit.credited입금이 Wallet 잔액에 반영된 때. 자동 매칭과 본사 지정 모두 같은 이벤트입니다.

요청 형식

POST로 보냅니다. Content-Type은 application/x-www-form-urlencoded; charset=utf-8이며 본문은 hook= 하나의 폼 필드에 JSON을 URL 인코딩해 담습니다. Webhook-Id 헤더에 발송 건의 고유 ID가 들어갑니다.

POST /your/endpoint
Content-Type: application/x-www-form-urlencoded; charset=utf-8
Webhook-Id: W95317172451...

hook=%7B%22eventType%22%3A%22transfer.settled%22%2C...%7D

hook을 URL 디코딩하면 다음 JSON입니다.

{
  "eventType": "transfer.settled",

  "status": "성공",
  "confirmedAt": "20261122211227",
  "trackId": "ORDER-0001",
  "walletId": "SAMPLE-WALLET",
  "amount": 50000,
  "acqTrxId": "261122000123"
}
{
  "eventType": "deposit.credited",
  "trxId": "D95317172451FB7C0",
  "status": "완료",

필드설명
eventTypetransfer.settled 또는 deposit.credited
trxId거래 ID. 송금은 송금 거래번호, 입금은 입금번호입니다. 중복 판정의 기준입니다.
status송금은 성공·실패, 입금은 완료
confirmedAt확정 시각 yyyyMMddHHmmss (서울)
walletId·amount대상 Wallet과 금액(원화 정수)
trackId·acqTrxId송금에만 있습니다. 고객사 주문번호와 기관 거래번호
depositName·sourceType입금에만 있습니다. 입금자명과 수신 경로(va·sms)

성공 판정과 재시도

HTTP 2xx로 응답하고 응답 본문에 0000을 포함해야 수신 성공으로 봅니다. 2xx라도 본문이 없거나 0000이 없으면 실패로 보고 다시 보냅니다. 본문에 0000만 적어도 됩니다.

실패한 통지는 1분 간격으로 최대 20회 다시 보냅니다. 그 뒤에는 멈추며 본사 운영자가 수동으로 재전송할 수 있습니다. 3xx는 따라가지 않습니다. 등록한 주소로만 보냅니다.

같은 거래의 통지가 두 번 이상 도착할 수 있습니다. trxId로 중복을 걸러 주세요. 보내지 않는 것보다 두 번 보내는 것이 낫다는 기준으로 처리합니다.

결과 코드

업무 응답은 HTTP 200 JSON입니다. 성공과 실패에 모두 resultCd, resultMsg, advanceMsg, createAt을 제공합니다. resultMsg는 간략한 결과이고, advanceMsg는 상세 결과입니다. 잔액·예금주 조회 및 원거래를 반환하지 않는 응답에서 createAt은 서울 기준 응답 생성 시각입니다. POST 이외의 메서드는 HTTP 405입니다.

코드의미
0000정상
W001요청 필드 또는 형식 오류
W002인증 키 또는 허용 IP 오류
W003API 운영시간 또는 기관 준비로 접수 중지
W004키에 연결된 Wallet 설정 오류
W009조회 거래 없음
W999원장 연결 또는 내부 오류

현재 가동 범위

잔액 조회와 원거래 조회를 제공합니다. 송금과 예금주 조회는 HYPHEN 시험 연결 전까지 접수 중지 상태(W003)로 응답합니다. WX 수수료는 서울 영업일 기준으로 일별 후불 차감합니다.
